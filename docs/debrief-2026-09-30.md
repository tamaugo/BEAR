## 1. What BEAR is

An autonomous eBay UK car-parts pricing pipeline. Three AI agents chained through the **pi agent harness** (v0.87.1, `@earendil-works/pi-coding-agent`); each agent's `.md` file IS its system prompt; no custom backend. Operator (Tamaugo/Alfie) sells **used parts off breakers' cars** — this business fact drove every design decision. Flow: photo(s) of car parts → part numbers → live eBay listings → priced, operator-formatted spreadsheet. One photo = one part; filenames carry location codes (`NSF/OSF/NSR/OSR` = near/off side front/rear) and `NULL` (operator already knows no number exists).

Invariants that must never break (downstream parses positionally): failure strings byte-identical (`FAILED | Could Not Produce Clear Part Number`, `No eBay Listing Found`, `eBay Lookup Unavailable`, `Malformed Input Line`); Agent 2 output `filename | part_number | name | price | url` (5 fields, URL may be empty); Agent 3 writes 4-field pipe-delimited `part info | price | url | image`; `make_xlsx.py` untouched; NULL photos skip vision+eBay entirely and reach Agent 3 directly.

## 5. The philosophy (why every piece looks the way it does)

1. **System One / System Two split.** LLMs (System Two) read, extract, transform — everything needing perception or generation. Jev (System One, RLCD-trained, typed probabilistic outputs, can't hallucinate) does ONLY calibrated decisions: choice/noul/score. Never use Jev for vision, text generation, or anything needing world knowledge beyond the state handed to it.
2. **Deterministic where arithmetic suffices; model where judgment is required; Jev where calibrated confidence is required.** Agent 2's price = consensus arithmetic (a pile-counting rule beats a pile-picking rule as the pile grows). Agent 3's format = rules + validator. Agent 1's pick = calibrated gate.
3. **Never demote a strength without testing the assumption that replaced it.** v9 assumed extraction was "cheap and reliable" without measuring; the live batch falsified it. The discipline to keep: when moving judgment from A to B, ask what A's old behavior was *also* doing incidentally (scrutiny, effort) — that incidental work must be explicitly reassigned, not silently dropped.
4. **Floor over average for no-failstate stages.** Agent 3 has no failstate — a bad row flows to the customer sheet — so score candidates on worst-run floor, not mean (this killed the contributor tiers and picked qwen3.8-flash).
5. **Repair mechanically, mark what needs judgment, never silently pass.** The validator pattern: repair what the rules define uniquely (sort, remap, price floor), mark the rest loudly (exit 2), stop before the deliverable. Bad rows reaching a customer are worse than a stopped run.
6. **Measurement culture: live or it didn't happen.** Every swap was A/B'd live on the operator's key at temp 0, multiple runs; failure data (which lines, which models) drove prompt surgery; cross-model failure on the same lines = rules problem, not model problem (proven: worked examples lifted every model).
7. **Downstream contracts are sacred.** Failure strings byte-identical, field order fixed, URLs copied verbatim, vehicle string passed verbatim — the operator's spreadsheet parser and his eyeballs depend on shape stability across versions.
8. **Babysitting model of AI delegation (how this work was produced):** heavy code generation goes to fresh Claude Code print-mode sessions (one discrete task per session, scoped `--allowedTools` incl. Edit when in-place edits are expected, tight `--max-turns`), the orchestrating agent validates claims against empirical data BEFORE files change, applies one-line fixes directly, and verifies independently (don't trust self-reports). Costs logged to `/home/hermes/bear-jev/usage-log.jsonl` (~$4.50 across 10 sessions). Key lessons: sessions die at turn caps → slice small; Edit permission denials recoverable from `~/.claude/projects/<dir>/<session>.jsonl`; "keep looping until you can't innovate anymore" (operator's standing directive) with usability counted alongside cost.
